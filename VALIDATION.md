# Проверки LampaWin 2.0.2

Дата изменений: 8–9 октября 2026 года. Версия выпуска — 2.0.2.
Исправления аудита выполнены на базе 2.0.0b / 2.0.0.1.

## Запуск и завершение в 2.0.2

Узкий сценарий `tools/testing/Run-LifecycleChecks.ps1 -Executable <EXE>`
запускает настоящие процессы приложения с отдельным профилем. Проверяются
закрытие во время запуска, готовность каталога, быстрый повторный запуск
и выход во время воспроизведения локального видео. После завершения проверяется
отсутствие принадлежащих сценарию дочерних служб и процессов WebView.
Для измерений используется монотонный счётчик времени.

В локальной проверке каталог был готов примерно через 2,2 секунды после начала
инициализации, до готовности Jackett/TorrServer. Завершение процессов заняло
0,17–0,23 секунды. В отчёте нового запуска отдельно измеряется время от создания
процесса до готовности каталога. Результаты сохраняются в `artifacts/checks/lifecycle-*`.

49 проверок Core включают открытие каталога без готовых служб и отмену
видеопотока, который сам не завершается. Эта проверка подтверждает отмену
сетевых запросов при выходе, а не качество внешней раздачи. Принудительное
завершение по шестисекундному пределу служит запасным путём для зависшего
нативного компонента; в успешных локальных сценариях он не потребовался.

## Автоматическая проверка

Один общий запуск: `tools/testing/Run-Checks.ps1`.
Он собирает solution, выполняет Core-проверки, JavaScript-мост и существующий
WPF/LibVLC UI smoke на синтетическом локальном видео. Новые регрессии проверяют
резервирование повреждённого профиля, повторную аутентификацию браузера,
ограниченное чтение ответа поиска, отключение фильтрации, команды следующей
серии, повтор с последней позиции и видимое предложение следующей серии.

Отчёты текущего запуска находятся в `artifacts/checks/`. Их результат и
ограничения записаны в `AUDIT-FIXES.md`. Исторические цифры не переносятся на
новый исходник автоматически.

На Windows-раннере CI может отсутствовать аудиоустройство. В таком случае
проверяется сохранение состояния видео после кнопки восстановления звука,
а недоступные аппаратные проверки явно перечисляются в `unavailableChecks`
отчёта UI. Проверки родного аудиовыхода и активной дорожки выполняются на
компьютере с доступным выходом Windows.

Отдельная узкая проверка `tools/runtime/Smoke --recovery-only` запускает только
собственные Jackett/TorrServer с временными данными, останавливает свой Jackett
и проверяет сохранение PID работающего TorrServer. Источники во внешней сети
не настраиваются. Это проверяет восстановление процессов, а не скорость раздачи.

## CI и дистрибутив

Workflow выполняет проверки на push, pull request и workflow_dispatch даже
без изменения номера версии. Публикация нового релиза зависит от успешной
валидации. Перед публикацией готовый EXE запускается с `--verify-package`:
загрузка компонентов, встроенного моста, WebView2 и воспроизведение локального
видео без каталога и внешних раздач. Результат проверки конкретного коммита
доступен в [GitHub Actions](https://github.com/Kryonex/LampaWin/actions/workflows/release.yml).
Релиз создаётся только после успешной проверки исходников и пакета.

## Приёмка на реальном оборудовании

| Сценарий | Что остаётся проверить |
| --- | --- |
| Чистая Windows 10 1809 и Windows 11 | Установка, отсутствие заранее установленного Runtime, первый запуск |
| Полный экран и доступность | Несколько мониторов, DPI, экранный диктор, клавиатура на реальных конфигурациях |
| Внешняя раздача | Старт, длительный просмотр, дальняя перемотка, слабый swarm, VPN/прямой маршрут |
| Звук | Физическая смена устройства Windows, отключение/возврат Bluetooth/USB во время фильма |
| Панель еды | SMS-вход, сохранение входа, окна OAuth/3-D Secure; оплата только с разрешения владельца аккаунта |
| Обновление | Установленная старая версия → строго новая; отмена, отказ установщика, откат, успешный перезапуск, сохранение профиля |
| Подписи | Настоящий сертификат издателя, Authenticode и CMS в реальном подписанном выпуске |
